# 도니홈 디자인

도니홈 UI 작업에는 [디자인 규칙](references/design-system.md)을 읽고 적용한다. 저장소의 `Theme.swift`와 `DonyControls.swift`가 구현 원본이다. macOS 기본 컨트롤의 모양에 기대지 않는다.

## 반드시 지킬 원칙

- 주요 화면에 글자 드롭다운 버튼을 새로 넣지 않는다. 필터는 행 선택·칩·분할 선택, 일괄 선택은 직접 버튼, 보관 기간 등 설정은 별도 설정창으로 표현한다.
- 실행 행동은 직접 버튼으로 노출한다. 같은 행동을 메뉴와 버튼에 중복하지 않는다. 드문 보조 행동만 공통 `DonyIconMenu`의 더보기로 넣는다.
- 기능을 소개하는 설명, 버튼을 다시 설명하는 문구, 내부 구현 설명은 본문에서 제거한다. 수치의 측정 기준은 `.help`나 상세로 옮긴다. 실제 오류·진행 상태·정리 제외 사유·파괴적 행동 확인은 유지한다.
- 본문은 Pretendard, 브랜드는 Fredoka, 색상·크기·간격은 `Theme`를 사용한다. `DonyTabs`, `DonyChoices`, `DonyFilterChips`, `DonyTextAction`, `SelectionControl` 등 공통 컴포넌트로 구현한다. 화면마다 네이티브 메뉴 화살표·배경·프레임을 조합하지 않는다.
- 제목·상태는 왼쪽, 실행은 오른쪽. 컨트롤 높이 42pt, 카드 여백 24pt·모서리 20pt·간격 20pt, 두 줄 목록 행 64pt. 카드 하나로 목록을 묶고 각 행에 `.panel()`을 붙이지 않는다.
- 작은 창에서도 수치·버튼이 겹치면 안 된다. 긴 이름은 한 줄로 줄이고 전체 경로는 툴팁으로 제공한다. 연결 도구가 많으면 칩은 수평 스크롤한다.
- 공통 컴포넌트 변경 시 전체 사용처를 점검한다. 밝은/어두운 Mac 환경, 최소 창 크기, 빈 결과, 긴 목록, 선택/비활성, 설정 열기/닫기를 실제 앱에서 확인한다. 외관 확인을 위해 사용자 파일 삭제·타 앱 종료·권한 변경을 하지 않는다.

## 저장소와 다른 Mac

저장소에 이 스킬과 `AGENTS.md`를 유지한다. `docs/design-system.md`가 규격 원본이고 이 스킬의 reference는 같은 내용의 설치용 사본이다. 규격 변경 시 둘을 함께 갱신한다. `scripts/check-design-rules.py`가 사본의 일치 및 개발/자원 화면의 드롭다운 재도입을 검사한다. 기존 다른 화면의 문자 메뉴는 유지보수 대상으로 남아 있으며 새 UI의 예외 근거가 아니다.

다른 Mac에는 저장소에서 `zsh scripts/install-design-skill.sh`를 실행한다. 앱 설치만으로 Codex 스킬이 설치되었다고 가정하지 않는다. 전역 설치 후 스킬 검색은 다음 대화 턴부터 적용된다.

UI 수정 후 `python3 scripts/check-design-rules.py`, 릴리스 빌드, 실제 화면 확인을 수행한다. 스킬 수정은 skill-creator의 `quick_validate.py`로 확인한다. 정적 검사 통과만으로 시각 검증을 완료했다고 보고하지 않는다.

명시적인 사용자 요청이 이 규칙보다 우선한다. 새 예외는 공통 변형으로 구현하고 적용 범위와 이유를 규격에 기록한다.
