# 도니홈 디자인 규칙

이 문서가 현재 UI 규격이다. `ui-consistency.md`는 과거 수정 기록이며 새 작업의 규격으로 사용하지 않는다. 도니홈은 도니의 간결한 정보 위계와 색상 방향을 참고한 네이티브 Mac 앱이며, 도니 공식 SDK나 인증 제품은 아니다.

## 구현과 토큰

색상·폰트·기본 버튼은 `Theme.swift`, 메뉴·설정 행·선택·검색·탭은 `DonyControls.swift`에서 관리한다.

| 대상 | 규격 |
|---|---|
| 본문 | Pretendard, 기본 14pt |
| 사이드바 브랜드 | 소문자 donyhome, Fredoka SemiBold 23pt (`Theme.brandFont`) |
| 화면 제목 | 28pt bold |
| 기본 버튼 | 높이 42pt, 모서리 10pt |
| 설정·유지보수 행동 열 | 전체 폭 128pt, 동일 오른쪽 끝 |
| 필터·일괄 선택 | 칩·분할 선택·직접 버튼, 높이 42pt |
| 더보기 메뉴 | 목록 32×32pt, 화면 도구 모음 42×42pt |
| 카드 | 흰 배경, 모서리 20pt, 기본 안쪽 여백 24pt |
| 카드 간격 | 기본 20pt |
| 주요 색 | `Theme.primary` #3182F6 |
| 보조 버튼 | `Theme.controlFill` #E8EBEF |
| 글자·보조 정보 | `Theme.body` / `Theme.secondary` |

## 버튼과 선택

- 주요 화면에 글자 드롭다운 버튼을 새로 넣지 않는다. 개발·CPU/메모리 화면의 필터는 행 선택·칩·분할 선택으로, 일괄 선택은 `SelectionControl`의 직접 버튼으로 구현한다. 보관 기간은 별도 설정창에서 `DonyChoices`를 사용한다.
- 제목·수치·상태는 왼쪽, 실행 행동은 오른쪽에 둔다. 설정·유지보수의 행동 열은 `SettingsActionRow`의 동일한 폭·높이·오른쪽 끝을 따른다.
- 바로 필요한 행동은 직접 버튼으로 노출한다. 한 영역의 주요 실행은 한 개다. 중복 진입 버튼을 만들지 않는다. 드문 보조 행동만 `DonyIconMenu`의 더보기로 넣고 접근성 이름·툴팁을 지정한다.
- `DonyTextAction`은 가벼운 선택·설정·필터 해제 행동, `DonyFilterChips`는 여러 도구 필터에 사용한다. 연결 도구가 많아도 칩의 높이는 42pt이며 가로 스크롤한다.
- 화면마다 `.menuStyle`, `.menuIndicator`, 배경·프레임·화살표를 조합하지 않는다. 더보기의 네이티브 메뉴 라벨은 텍스트만 사용하고 아이콘은 바깥에서 그린다. 클릭 영역은 배경 전체다.
- 일괄 선택은 추천 선택(있는 경우)과 전체 선택/선택 해제를 직접 노출한다. 목록의 실행 버튼은 선택 상태에 대응한다.
- 모든 주요 화면의 글자 드롭다운을 금지한다. 기존 `DonyMenuButton` 구현은 제거했다. 클립보드 고정 단축키의 드문 보조 하위 메뉴는 더보기 내부에만 허용하며 설정의 주요 키 선택은 별도 창에서 한다.

## 화면과 한국어

| 메뉴 | 역할 |
|---|---|
| 전체 검사 | 검사 → 결과 → 추천 대상 검토 → 실행 |
| 캐시·로그 | 다시 생성 가능한 앱 임시 파일 |
| 파일 검사 | 큰 파일·오래된 파일·중복/유사 파일 찾기 |
| 폴더 용량 | 선택한 폴더의 용량 분포·하위 폴더 탐색 |
| CPU·메모리 | 현재 자원 사용과 앱/프로세스 관리 |
| 개발 | 도구별 캐시·로그 정리, 실행 자원 확인과 작업 관리 |
| 배터리 관리 | 지원 기기의 충전 제어 |
| 클립보드 | 복사 기록과 붙여넣기 편의 기능 |
| 앱 관리 | 설치 앱과 관련 로컬 파일 관리 |
| 유지보수 | 휴지통·DNS·검색 색인·로컬 백업 작업 |

‘용량 지도’, ‘잔여물 후보’처럼 역할을 추측하게 하는 표현 대신 대상과 행동을 적는다. 검사·정리·종료를 구분하고 ‘다시 검사’ 다음에는 결과를 볼 수 있게 한다. 기능 소개·버튼 재설명·일반적인 내부 구현 설명은 본문에서 제거한다. 수치의 측정 기준은 툴팁이나 상세에 둔다. 실제 오류·진행 상태·정리 제외 사유·파괴적 행동 확인은 남긴다. 경로는 긴 글자를 줄여 보여도 툴팁/상세에서 전체 경로를 확인할 수 있어야 한다.

## 목록·그래프·확인창

- 목록의 높이는 콘텐츠로 결정한다. 행 안의 수직 `Spacer`나 무제한 높이로 빈 공간을 늘리지 않는다. 작은 행마다 큰 카드를 만들지 않는다.
- 두 줄 기록 목록은 `Theme.listRowHeight` 64pt, 빠른 선택 목록의 텍스트 행은 `Theme.quickRowHeight` 36pt다. 목록 전체에 카드 하나를 적용하고 행 사이는 구분선으로 나눈다. `*Row` 컴포넌트 안의 `.panel()`은 CI에서 거부한다. 사용자가 조절한 빠른 창 이미지 높이는 이미지 행에만 적용한다.
- 클립보드 설정은 일반·보관·모양·고정·제외·고급 탭으로 구분하고 설정 버튼을 화면 상단에 바로 노출한다. 섹션 하나에 공통 카드 하나를 사용하며 기능마다 새로운 카드/버튼 규격을 만들지 않는다.
- 클립보드의 기본 진입은 전역 단축키로 여는 빠른 목록이다. 본창이나 사이드바 클릭을 요구하지 않는다. 팝업은 본창을 활성화하거나 앞으로 올리지 않고 검색/키보드 선택을 받는다. 본창은 기록 관리용 보조 화면이다. 단축키 등록 실패를 성공 상태로 표시하지 않는다.
- 그래프와 용량 막대에는 hover로 이름·값을 보여주고 접근성 이름을 제공한다. 색만으로 항목을 구별하게 하지 않는다.
- 팝업과 설정은 본문과 같은 폰트·버튼·색상 체계를 사용한다. Mac에서 네이티브 동작이 필요한 메뉴와 권한 창은 해당 시스템 동작을 유지한다.
- 삭제·휴지통 이동 확인에는 대상, 수량, 용량과 복구 가능 여부를 표시한다. 영구 삭제의 기본 키는 취소다. 위험 설명을 ‘불필요한 설명’으로 취급하지 않는다.
- 권한 부족, 파일 상태 변경, 응답 시간 초과를 구분한다. 권한 안내에서 재시작·검사 이어가기의 결과를 명확히 한다.

## 검증과 변경

1. `python3 scripts/check-design-rules.py`: 개발/자원 화면의 문자 드롭다운 재도입, 개별 메뉴 스타일 우회, 공통 컴포넌트와 설치용 스킬 reference의 일치를 검사한다. GitHub Actions에서도 실행한다.
2. `zsh scripts/build-app.sh`: SwiftUI 타입/리소스와 서명을 검증한다.
3. 실제 앱에서 변경 화면과 공통 컴포넌트 사용처를 확인한다. 창 폭을 줄이고 긴 이름·빈 상태·선택·비활성·메뉴 열기/Escape 상태를 확인한다.
4. 정렬·크기·클릭 범위는 실제 렌더링으로 판단한다. 정적 검사 통과만으로 시각 품질이 검증됐다고 보고하지 않는다.

규격을 바꿀 때는 토큰/공통 컴포넌트와 이 문서를 함께 수정한다. GitHub 규칙 검사는 소스의 우회를 막는 보조 수단이며 스크린샷 기반 시각 검사를 대체하지 않는다.

## 권한과 첫 실행

- 첫 설치는 권한 설정부터 온보딩을 표시한다. 알림·손쉬운 사용·다운로드·데스크탑·문서 접근 요청을 한 차례 진행하고 전체 디스크 접근 설정으로 안내한다. OS가 허용하는 권한 요청은 시스템 창을 사용하며 앱이 대신 허용하지 않는다.
- 각 권한 행은 상태 아이콘과 상태 글자를 함께 표시한다. 파일 접근은 실제 읽기 접근으로 확인한다. 전체 디스크 접근의 공개 조회 API가 없으므로 보호된 파일 접근 결과를 표시하고, 대상 부재·기타 오류는 ‘확인 필요’로 표시한다. 검사 오류가 없다는 이유로 허용 상태를 추측하지 않는다.
- 권한 요청을 시작했다는 기록은 온보딩 완료와 별개다. macOS가 권한 변경으로 종료해도 미완료 온보딩이 다시 나타나며 자동 요청을 반복하지 않는다. 권한 요청 시작 버튼으로 재시도할 수 있다.

브랜드 폰트 Fredoka는 앱에 함께 포함하며 SIL Open Font License를 `Resources/Fonts/Fredoka-OFL.txt`에 보관한다. 본문·메뉴·설정은 기존 Pretendard 규격을 사용한다.

- 온보딩은 권한(허용 n/6 요약·주요 버튼 하나) → 개발 도구(감지된 도구 우선, 나머지는 접힘) → 프로젝트(진입 시 자동 탐색, 프로젝트별 선택) → 준비 완료(연결 요약·캐릭터) 순서다. 화면 검토용 DEBUG 픽스처는 권한을 요청하지 않는다.

## 도니 소개

‘도니’는 사이드바 맨 아래에 고정하고 기존 메뉴와 동일한 폭·클릭 영역을 사용한다. 소개와 만든 이유는 공통 카드를 사용하며 경력 목록은 표시하지 않는다. LinkedIn은 기존 Phosphor 아이콘과 공통 128pt 행동 버튼으로 표시한다. 복사·개인 연락처 수집 같은 추가 행동은 넣지 않는다.

## 홈·개발·기기 관리

- 홈의 중심은 Mac 일러스트와 ‘전체 검사’ 행동 하나다. 이 중앙 행동은 홈에만 허용하며 다른 화면의 작업 버튼은 공통 오른쪽 행동 영역을 따른다. 상태 수치는 한 카드로 요약한다.
- 개발은 도구 정리·작업·연동·프로젝트·캐시 탭으로 나눈다. 첫 화면은 연결된 모든 도구의 64pt 행으로 캐시·로그, 정리 가능 용량, 실제 메모리·CPU를 보여준다. 경로 미확인·검사 전·사용 중·최근 파일을 구분한다. 도구 선택은 해당 파일 목록과 작업 필터로 이어진다. 프로젝트는 보조 탭이며 기존 용량 분포·선택 상세를 유지한다.
- 메모리 압박은 작업 검토 안내만 표시하며 파일 정리를 자동 실행하지 않는다. 도구 파일 정리는 검토한 개별 캐시·로그만 휴지통으로 이동한다. 실행 중 캐시·열린 파일·대화·인증·소스·보관 원본은 보호한다.
- 프로젝트 용량 면적은 바이트에 비례한다. hover와 접근성 이름에 이름·용량·일부 결과 여부를 표시한다. 그래프 클릭은 상세 선택이며 정리 체크박스와 별개다.
- 전체 검사 상태는 실제 검사 단계만 표시한다. 추정 진행률이나 검사하지 않은 보안·메모리 최적화 성공을 표시하지 않는다. 중단 결과는 일부 결과로 표시한다.
- 공간 부족 알림과 읽기 전용 추천 검사는 별도 옵션이다. 자동 추천 검사가 기존 전체 검사 결과를 지우면 안 된다. 자동 추천은 파일을 삭제하지 않는다.
- 정리 결과는 이동/삭제한 바이트와 실제 가용 공간 변화의 측정값을 구분한다. 휴지통 이동을 공간 확보라고 표현하지 않는다. 측정은 첫 파일 변경 직전에 시작한다.
- 작업 일시 정지는 RAM을 유지한다. 검증된 로컬 CLI만 사용자 선택으로 제어하고 현재 호스트·작업 폴더를 보호한다. 클라우드 작업별 제어 또는 GUI 앱 내부 작업 제어를 지원하는 것처럼 표현하지 않는다.

## 다른 Mac에서도 같은 규격 유지

- 저장소의 `.agents/skills/donyhome-design`는 전역에 설치 가능한 독립 스킬이다. reference는 이 문서와 같은 내용이어야 하며 CI가 일치를 검사한다.
- `zsh scripts/install-design-skill.sh`는 현재 Mac의 Codex 전역 스킬 경로에 설치한다. 기존 스킬은 `skill-backups`에 보관하며 다른 스킬은 변경하지 않는다. 스킬은 다음 대화 턴부터 검색된다.
- 색상은 시스템 accent에 의존하지 않고 공통 토큰으로 지정한다. Pretendard/Fredoka와 아이콘을 앱에 포함하고 콘텐츠의 색상 모드를 앱 수준에서 고정한다. 최소 창 크기에서 실제 버튼·수치·목록을 확인한다.
- 앱만 설치한 다른 Mac에서는 스킬이 자동으로 설치되지 않는다. 배포 ZIP에 포함한 스킬 설치 스크립트를 별도로 실행한다.

## 2.3.0 정리 추천 화면

- 공통 보관 기간은 사용자 설정을 사용한다. 14일은 기본값이며 1–3650일 입력과 단축 선택을 제공한다. 캐시·로그·개발 캐시·도구·프로젝트에 같은 설정을 전달한다. 기간 변경은 이전 추천 계획을 무효화한다.
- 캐시·로그는 발견·추천·보관을 같은 카드에서 구분한다. 앱/경로별 64pt 행으로 집계하고 선택한 경로의 개별 추천 파일을 보여준다. 검사 제한·권한 오류 등 미측정이 있으면 ≥와 실제 일부 결과 상태를 표시한다.
- 실행 중 캐시는 보관한다. 사용 중인 개발 도구의 오래된 로그는 프로세스 시작 정보·열린 파일의 경로/파일 식별자를 확인한 경우에만 추천하며, 실행 직전 다시 확인한다. 확인 불가는 보관이다.
- 휴지통과 백업은 검사·목록 선택을 직접 노출한다. 영구 삭제 확인을 유지한다. 클립보드 선택 설정은 분할 선택, 고정 키 선택은 별도 설정창을 사용한다.

- 후보 목록은 100개씩 이전·다음 직접 버튼으로 이동한다. 첫 100개만 영구적으로 잘라내지 않는다. 필터·검사 변경은 첫 페이지로 돌아간다. 전체 선택은 페이지와 무관하게 모든 추천 후보를 포함한다.

- 페이지 제목은 한 번만 표시한다. 사이드 메뉴를 바꾸면 콘텐츠 스크롤은 처음으로 돌아간다. 창 크기 변경 자체는 현재 내용을 재설정하지 않는다.

## 빠른 클립보드의 실제 동작

- ⌘1–9는 화면에 붙은 번호의 항목을 실제 클립보드로 복사한다. 검색 결과와 고정 항목을 반영해 번호 표시와 실행 대상이 일치해야 한다. 복사 성공 후 빠른 창을 닫고, 실패 시 창과 오류를 유지한다.
- 키보드 선택 배경과 실제 클립보드 상태는 구분한다. 현재 클립보드 항목은 확인된 복사 결과로 표시하며, 외부 복사·비공개/일시정지 캡처로 상태를 확인할 수 없으면 표시를 해제한다.
- 설정 버튼과 ⌘,는 빠른 창과 독립된 공통 설정창을 연다. 이 앱의 정리 확인창이 열린 동안에도 빠른 창·설정창은 입력을 받는다. 설정창의 키를 빠른 목록 단축키로 가로채지 않는다.

- 빠른 창의 숫자는 최근 복사 순서로 매번 다시 붙는다. 관리 화면의 별도 정렬 선택이 빠른 창 번호를 고정하지 않는다. 항목 복사에 성공하거나 창이 열린 동안 시스템 클립보드가 바뀌면 빠른 창을 닫는다. 기록 일시정지/제외 설정은 기록 여부에만 적용하며 닫기 동작을 막지 않는다.

## 클립보드 전체 지우기 예외

- 사용자의 한 번 클릭 요청에 따라 클립보드 ‘전체 지우기’는 별도 확인창 없이 저장 기록·고정 항목·현재 복사 내용을 즉시 비운다. 화면은 0개와 빈 목록으로 즉시 갱신한다. 이 예외는 클립보드 전체 지우기에만 적용하며 다른 파일 삭제·휴지통·프로세스 제어의 확인 규칙은 유지한다.

## 확인창 버튼의 실제 실행

- SwiftUI 버튼 안에서 `runModal` / `stopModal`로 중첩 이벤트 루프를 만들지 않는다. 공통 `ConfirmationDialog.show`를 비동기로 기다리고, 네이티브 폴더 선택은 `OpenPanelPresenter`의 완료 콜백을 사용한다.
- 원래 버튼 처리가 반환된 뒤 확인창이 입력을 받도록 한다. 실행·취소·Escape·Enter·닫기 모두 요청을 한 번만 완료해야 한다. 영구 삭제와 파괴적 행동의 Enter는 취소를 유지한다.
- 확인창을 기다리는 동안 중복 검사·변경을 막고, 동의 후에도 파일·프로세스·설정의 현재 상태를 재확인한다.
- 확인창 버튼 검사에서는 화면에 그려진 버튼에 실제 마우스 이벤트를 보내 실행·취소 결과를 확인한다. `completion(true)` 직접 호출이나 함수 단독 테스트만으로 클릭 검증을 대체하지 않는다. 정리 동작은 테스트에서 생성한 임시 파일과 격리된 기록·클립보드로 검증한다.
- `python3 scripts/check-ui-actions.py`로 동기 모달 루프 재도입을 차단한다. 확인창·설정창의 실행 버튼과 완료 버튼까지 실제로 클릭해야 완료 보고가 가능하다.
