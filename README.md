# donyhome · 도니홈

Dony의 Mac에서만 사용하는 저장 공간 정리·성능 관리 앱. macOS 14 이상, SwiftUI/AppKit. 서버·계정·외부 API·추가 런타임 없이 실행합니다.

## 실행

UI 작업 규격: [도니홈 디자인 규칙](docs/design-system.md), [디자인 스킬](.agents/skills/donyhome-design/SKILL.md), [저장소 작업 규칙](AGENTS.md). `python3 scripts/check-design-rules.py`는 GitHub Actions에서도 실행됩니다.

다른 Mac의 Codex에도 디자인 규칙을 설치하려면 저장소에서 `zsh scripts/install-design-skill.sh`를 실행하세요. 배포 ZIP에도 설치 스크립트와 독립 스킬을 포함합니다. 다음 대화 턴부터 적용됩니다.

```sh
./scripts/build-app.sh
open build/DonyHome.app
```

Finder에서 `build/DonyHome.app`을 `~/Applications`로 옮겨 사용할 수 있습니다. 로그인 시 실행을 사용할 경우 이동한 앱을 실행한 뒤 앱 설정에서 켜세요. 현재 빌드는 개인 로컬 사용을 위한 ad-hoc 서명입니다.

## 기능

### 2.3.13: 정리 추천 검토 화면
- 정리할 항목에서 `검토`를 누르면 개발 캐시 전체가 아니라 추천 항목만 모두 선택된 채로 열려요. 상단에 추천 사유가 나오고 `전체 보기`로 나머지를 볼 수 있어요.
- 캐시·로그, 동일한 파일 사본, 개발 캐시 행에도 추천 사유를 보여줘요.

### 2.3.12: 추천 제외 · 미리보기 · 정리 버튼 위치

- 목록의 각 항목 「⋯」 메뉴에서 「미리보기」(macOS 빠른 보기)와 「다시 추천하지 않기」를 쓸 수 있습니다. 제외한 항목은 추천 계산에서 빠지고 「추천에서 제외됨」으로 표시되며, 직접 선택은 그대로 할 수 있습니다. 「추천 기준」에서 제외 개수를 보고 초기화합니다.
- 전체 검사 결과 상단에 「선택 항목 정리 · 용량」 버튼을 두어 스크롤 없이 바로 정리할 수 있습니다. 추천이 0개인 줄의 「검토」는 비활성입니다.
- 화면 검토용 DEBUG 전용 픽스처(`ReviewUIFixture`)를 추가했습니다. 릴리스 빌드에는 포함되지 않으며 임시 폴더의 가짜 항목만 사용합니다.

### 2.3.11: 되돌리기 · 검토 시 추천 미리 선택

- 정리 후 완료 카드에 「되돌리기」(방금 옮긴 항목을 원래 위치로 복원)와 「휴지통 비우기」(휴지통 목록을 검사한 상태로 열기)를 추가했습니다. 전체 검사 화면에서도 결과가 사라지지 않고 보입니다.
- 정리 기록의 각 항목에도 「되돌리기」가 생겼습니다. 원래 위치에 같은 이름이 있으면 덮어쓰지 않고, 휴지통 바로 아래 항목과 홈 폴더 안 경로만 복원합니다.
- 전체 검사의 「검토」가 캐시·로그, 중복 사본에서도 추천 항목을 미리 선택한 채로 엽니다.

### 2.3.10: 전체 검사의 작업공간 추천 검토

- 전체 검사에서 「방치된 작업공간」을 「개발 캐시」와 분리해 개수·용량·추천 사유를 행에 표시합니다. 「추천 기준」에도 작업공간 기준을 추가했습니다.
- 「검토」를 누르면 개발 캐시 화면이 추천 항목을 이미 선택한 채로, 추천 항목을 맨 위에 두고 열립니다. 항목마다 활동 없음 기간과 변경·미푸시 여부를 보여줍니다.

### 2.3.9: 파일 검사 통합 · 개발 프로세스 종료

- 「폴더 용량」을 별도 메뉴에서 「파일 검사」의 탭으로 옮겼습니다. 큰 파일·중복·오래된 파일·설치 파일·유사 사진과 같은 폴더 선택·검사 흐름을 씁니다.
- CPU · 메모리의 「내 프로세스」에서 GUI 앱이 아닌 내 CLI 프로세스도 종료를 요청할 수 있습니다. CPU 50% 이상으로 10분 넘게 도는 것, 300 MB 이상을 6시간 넘게 쓰지 않고 잡고 있는 것은 「추천 선택」에 담깁니다. 일반 종료(SIGTERM)만 보내며 셸·claude·ssh·`.app` 내부·시스템 경로는 제외합니다.

### 2.3.8: 방치된 AI 작업공간 정리

- `~/.codex/worktrees`, `~/.claude/worktrees`의 git 작업공간이 개발 정리·스마트 점검에 추천으로 나옵니다. 설정한 보관 기간 이상 활동이 없고, 커밋하지 않은 변경·원격에 없는 커밋·해당 폴더에서 실행 중인 프로세스가 없을 때만 추천합니다. 생성물이 아닌 무시 파일이 5 MB를 넘으면 직접 확인으로 남깁니다. 실행 직전에 같은 검사를 다시 하며 휴지통에서 복원할 수 있습니다.

### 2.3.7: 확인창 버튼과 전체 행동 점검

파일 정리·앱 종료·개발 작업·유지보수·배터리 확인창을 비동기 방식으로 바꿨습니다. SwiftUI 버튼 안에서 화면 처리를 붙잡던 동기 모달 루프를 제거했고 폴더/제외 앱 선택창도 함께 수정했습니다. 실행 전 상태 재확인, 중복 요청 방지, Enter/Escape·취소·닫기 처리를 검증했습니다. [버튼 점검 기록](docs/ui-action-audit-2.3.7.md)에 소스 전수 조사와 실제 클릭 검증 범위를 구분했습니다.

### 2.3.6: 전체 지우기 한 번으로 바로 비우기

- 하단 ‘전체 지우기’를 한 번 누르면 확인창 없이 기록·고정 항목·현재 복사 내용을 즉시 비웁니다. 같은 팝업에 0개와 빈 목록을 표시합니다.

### 2.3.5: 클립보드 확인창 입력 차단 수정

- 전체 지우기 확인창을 앱 입력을 막지 않는 방식으로 표시합니다. 설정·취소 버튼이 클릭되지 않던 문제를 수정하고 확인창이 중복으로 열리지 않게 했습니다.
- 전체 지우기를 완료하면 기록·고정 항목과 현재 시스템 클립보드 내용을 모두 비웁니다. 기록이 없어도 현재 복사된 내용이 있으면 실행할 수 있습니다. 취소 시에는 모두 유지합니다.

### 2.3.4: 클립보드 전체 지우기

- 빠른 창 하단의 ‘전체 지우기’로 고정 항목을 포함한 모든 기록을 삭제합니다. 개수와 복구 불가 안내를 확인한 뒤 실행하며 빈 기록에서는 비활성화됩니다. 시스템에 현재 복사된 내용은 유지합니다.

### 2.3.3: 빠른 창의 오래된 목록 수정

- 빠른 창을 열기 직전에 복사를 수집하고, 매번 최신 기록으로 화면과 번호를 다시 구성합니다. 숨겨진 팝업이 이전 목록을 계속 보여주던 문제를 수정했습니다.
- 메뉴 추적·정리 확인창의 중첩 실행 중에도 복사 감지가 동작합니다. 팝업을 새로 구성할 때 이전 키보드 감시자를 해제해 단축키가 중복 실행되지 않게 합니다.

### 2.3.2: 빠른 클립보드 실제 동작

- 번호는 최근 복사 순서입니다. 마지막 복사 항목이1번으로 올라오며, 관리 화면의 별도 정렬이 빠른 창 번호를 고정하지 않습니다.
- ⌘1–9와 항목 클릭은 실제 클립보드를 바꾸고 성공 시 창을 닫습니다. 빠른 창을 연 상태에서 외부 복사가 발생해도 닫힙니다. 실패한 복사는 오류와 창을 유지합니다.
- 현재 복사 항목 표시를 키보드 선택 배경과 구분하며 외부 변경·내용 편집 시 갱신합니다.
- 설정은 독립 창으로 열립니다. 정리 확인창이 열린 상황의 입력 차단을 보강하고, 설정을 닫으면 단축키 녹화를 중단합니다. [Maccy 원본과 동작 비교](docs/clipboard-maccy-review.md).

### 2.3.0: 개별 파일 추천 · 공통 보관 기간

- 설정한 보관 기간(기본 14일, 1–3650일)을 캐시·로그·개발 캐시·도구·프로젝트 추천에 공통 적용합니다. 변경 시 이전 추천 계획을 무효화합니다.
- 캐시·로그를 개별 파일로 추천하고 앱/경로별 발견·추천·보관 용량을 보여줍니다. 최근 파일이 섞인 폴더도 오래된 파일을 따로 검토할 수 있습니다. Google/Aside/Codex와 알려진 Electron 캐시, pnpm 캐시를 추가했습니다. pnpm 패키지 저장소·프로젝트·DB·계정 정보·오프라인 클라우드 데이터는 보호합니다.
- 각 검사는 전체 경로를 합쳐 후보 최대 2만 개·메타데이터 최대 100만 개·120초로 제한하고, 미측정 경로가 있으면 일부 결과와 ≥로 표시합니다. 실행 중 캐시는 보관합니다. 활성 개발 도구의 오래된 로그는 현재 사용자 프로세스 목록과 열린 파일 상태를 완전히 확인한 경우에만 추천하고 실행 직전 다시 확인합니다. 목록 누락·프로세스 변경·읽기 실패 시 도구 파일은 보관합니다. DB의 WAL/SHM/journal 보조 파일도 보호합니다.
- 파일 상세는 100개씩 이전·다음 페이지로 검토할 수 있고 전체 선택은 모든 후보에 적용합니다. 대량 추천은 경로 인덱스로 중복을 제거하고 변경 없는 계획을 재사용합니다.
- 클립보드·유지보수에 남아 있던 문자 드롭다운을 제거했습니다. 전체 선택·분할 선택·설정창을 공통 컴포넌트로 사용합니다. 휴지통 이동과 실제 가용 공간 변화는 구분합니다.

### 2.2.1: 개발 도구 정리

- 모든 연결 도구를 공통 화면에서 관리합니다. 도구별 캐시·로그·정리 가능 용량과 실행 프로세스 CPU·메모리를 표시하고, 오래된 비사용 도구 파일만 검토 후 휴지통으로 이동합니다. 확인되지 않은 캐시 경로는 명시하며 폴더 연결·로컬 작업 제어는 도구별 지원 범위를 따릅니다. 대화·인증·프로젝트 소스는 보호합니다.
- 개발·CPU/메모리 화면은 글자 드롭다운 없이 행·칩·분할 선택과 직접 버튼을 사용합니다. 전체 선택은 공통 직접 버튼, 보관 기간은 별도 설정창입니다. 불필요한 설명을 제거했고 실제 제외 사유는 유지합니다. 전역 디자인 스킬과 CI 규칙이 같은 규격을 적용합니다.
- 메모리 압박은 작업 확인으로 안내합니다. 파일 정리와 CLI 일시 정지는 RAM 확보로 표시하지 않습니다. CLI 작업 종료는 작업 탭에서, GUI 앱 종료는 CPU·메모리 화면에서 직접 선택합니다. [연동과 정리 범위](docs/development-integration.md).

### 2.0: donyhome · 배터리 관리 · 클립보드

- 앱과 저장소 이름을 donyhome으로 변경했습니다. 기존 정리 기록과 설정을 유지하기 위해 내부 bundle identifier와 기존 기록 경로는 그대로 사용합니다. 실행 파일/앱은 DonyHome이며 새 기능의 기록은 별도 로컬 경로에 저장합니다.
- 배터리 관리: [battery](https://github.com/actuallymentor/battery)의 실제 CLI 엔진을 원본 기능에 맞춰 통합했습니다. 충전 상한/범위/전압 유지, 강제 방전, 충전·어댑터 제어, 목표 충전/방전, 보정, 중단·복원, 로그, 재시동 후 유지, 오프라인 설치/제거를 제공합니다. Apple Silicon MacBook용이며 내장 배터리가 없는 Mac mini에서는 제어가 비활성화됩니다. 명령 완료와 실제 하드웨어 상태를 구분합니다.
- 설치는 사용자 행동과 macOS 관리자 인증을 거칩니다. 원본 스크립트는 네트워크 업데이트 없이 앱별 경로로 분리했고, 관리자 권한은 17개의 정확한 SMC 쓰기 명령으로 제한합니다. 기존 battery 설치를 자동 덮어쓰지 않습니다. 제거는 충전 복원 확인 후 앱의 도구만 제거합니다. [배터리 통합/검증 범위](docs/battery-integration.md).
- 클립보드: [Maccy](https://github.com/p0deje/Maccy)의 실제 캡처·개인정보 제외·정렬·검색·키보드 처리 코드를 기존 디자인으로 통합했습니다. 텍스트/서식/이미지/여러 파일, 로컬 OCR 검색, Fuse 검색, 고정·순서·단축키, 편집, 기록 제한·정렬, 제외 앱/타입/텍스트, 일시 정지·다음 복사 제외, 순서대로 붙여넣기를 제공합니다.
- 기본 `⇧⌘C`로 빠른 클립보드 창을 엽니다. 단축키를 변경할 수 있고, Enter 복사/Option-Enter 붙여넣기/Option-Shift-Enter 일반 텍스트 붙여넣기를 지원합니다. 붙여넣기는 사용자의 손쉬운 사용 권한과 이전 앱의 포커스·클립보드 상태 검증을 거칩니다. 설치 당시 클립보드 내용을 자동 가져오지 않습니다. [클립보드 통합/원본 대비 범위](docs/clipboard-integration.md).
- MIT 라이선스의 battery/Maccy/Fuse와 GPLv2의 별도 SMC 실행 파일·정확한 소스를 함께 포함합니다. 설정 → 앱 정보에서 출처와 라이선스를 볼 수 있습니다. 원본 앱의 독립 실행 UI/자동 업데이트/앱별 Intents는 donyhome의 앱 구조에 맞춰 대체하거나 포함하지 않습니다.


### 1.3: 화면 정리 · 캐릭터 미리보기

- 설정/유지보수의 행동은 제목 왼쪽, 행동 오른쪽의 공통 행으로 통일합니다. 자동 정리는 설정에 모으고, 목록 선택은 공통 직접 버튼으로 제공합니다.
- 캐시·로그는 임시 파일 검사, 파일 검사는 선택한 폴더의 큰 파일·중복·사진 검사, 폴더 용량은 공간 사용 분석입니다. 개발 캐시는 개발 메뉴에 있습니다. 앱 관리의 남은 앱 파일은 연결된 앱을 찾지 못한 파일이며 사용자 데이터가 포함될 수 있습니다.
- CPU·메모리는 요약 두 개와 앱 목록을 기본 표시하고 프로세스 범위/스왑/압축 정보는 상세로 분리합니다.
- 캐릭터는 여유 시 커피를 마시며 느리게 코딩하고, 메모리 압박 또는 높은 CPU 사용 시 땀을 흘리며 빠르게 코딩합니다. 컬러/흑백 설정과 초기 설정에 두 상태의 애니메이션 미리보기를 제공합니다. CPU 온도를 측정하는 기능은 아닙니다.
- 파일 작업 확인창은 앱의 공통 디자인으로 전체 대상 경로와 취소/실행 버튼을 표시합니다. 위험한 작업에서 Return은 취소, Escape는 취소입니다. 접근 거부는 Cocoa/POSIX 오류 코드와 underlying error로 식별해 권한 안내와 설정 진입을 제공합니다. 같은 실패 경로 집합은 실행 중 한 번 자동 안내하고 배너에서 다시 열 수 있습니다. 실측에서 폴더 읽기가 응답하지 않은 Music 캐시는 검사에서 제외하며, 이를 권한 거부로 분류하지 않습니다.

### 1.2: 개발 도구 연결 · 온보딩

- 첫 실행에 도구 다중 선택, 프로젝트 연결, 필요한 macOS 권한 안내, 캐릭터 컬러/흑백 설정을 제공합니다. 초기 설정은 앱 설정에서 다시 열 수 있습니다. 알림·폴더 접근·전체 디스크 접근은 사용자가 macOS에서 허용합니다.
- 개발 도구를 동시에 식별하고 부모/자식 프로세스를 도구별로 묶습니다. Herdr, Orca, cmux, tmux, 터미널과 Claude/Codex/Hermes/Cursor, OpenCode/Gemini/Aider/Copilot/VS Code/Windsurf를 지원합니다. 식별되지 않은 인터프리터는 기타 개발 프로세스로 표시합니다. 명령행은 실행 파일/스크립트 이름만 판별하고 프롬프트·환경 변수는 저장하지 않습니다.
- Herdr `api snapshot`, Orca `worktree ps --json`, cmux `list-workspaces --json`, tmux `list-panes`의 읽기 전용 결과와 실행 중인 로컬 프로세스의 작업 경로에서 프로젝트를 찾습니다. CLI 설치·실행이 필요한 도구는 연결 상태로 안내합니다. 원격 호스트 경로는 제외합니다. 발견한 폴더는 사용자가 선택하기 전까지 정리하지 않습니다. 도구가 설치되지 않은 환경에서는 실제 연결 대신 응답 형식 테스트로 검증했습니다.
- 메뉴 팝업은 CPU·메모리·압박·저장 공간·배터리·네트워크 송수신률과 하나의 앱 열기 버튼으로 구성합니다. 네트워크 수치는 현재 전송률이며 회선 최대 속도 측정은 아닙니다.
- CPU 목록은 56pt 행과 현재 표시 목록 전체 선택/선택 해제를 제공합니다. 시스템 앱과 도니홈 자체는 종료 선택에서 제외됩니다. 앱을 다시 열면 닫거나 최소화한 메인 창을 복원합니다.
- 용량 막대는 hover 시 항목·용량 표시, 클릭 시 폴더 탐색을 제공합니다. 사용량 그래프는 hover 지점의 값을 표시합니다.

연동 자료: [Herdr Socket API](https://herdr.dev/docs/socket-api/), [Orca CLI](https://www.onorca.dev/docs/cli/overview), [cmux API](https://cmux.com/docs/api).

### 자동 정리 · 프로젝트 관리

- 메뉴 막대에는 27×18pt 픽셀 코딩 캐릭터만 표시합니다. 여유로울 때는 0.65초, CPU 50% 이상 또는 메모리 주의일 때는 0.22초, CPU 85% 이상 또는 메모리 부족일 때는 0.10초 간격으로 타이핑합니다.
- 안전 자동 정리: 사용자가 설정한 보관 기간이 지난 확인된 앱 캐시·로그 파일를 개별 판별해 휴지통으로 이동합니다. 같은 폴더의 최근 파일은 유지합니다. ‘지금 자동 정리’와 ‘하루 한 번 자동 정리’를 제공하며, 예약 정리는 기본 꺼짐이고 앱 실행 중에만 작동합니다. 휴지통은 자동으로 비우지 않습니다.
- 별도 개발 메뉴에서 식별 가능한 앱·CLI와 작업 프로세스를 모니터링합니다. 일반 GUI 앱은 종료 요청할 수 있습니다. 브라우저 탭과 도구를 식별할 수 없는 일반 작업 프로세스의 개별 도구 귀속은 보장하지 않습니다. API 계정 연결 없이 이 Mac의 프로세스와 경로를 사용합니다.
- 프로젝트 보관 기간: 기본 14일, 1~3650일 사용자 지정과 1/2/3/7/14/30일 단축 버튼. 최근 파일·디렉터리 수정 시각과 로컬 작업 이력 중 더 최근 시각을 적용합니다.
- 정리 범위: ‘빌드 · 캐시만’ 또는 ‘프로젝트 전체 · 소스 포함’. 생성물 범위는 `.next`, `.nuxt`, `.svelte-kit`, `.parcel-cache`, `.turbo`, `node_modules/.cache`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`로 제한합니다. 일반 `build`, `dist`, 전체 `node_modules`는 사용자 파일을 포함할 수 있어 자동 추정하지 않습니다.
- 프로젝트 찾기: 직접 등록 / 작업 이력 / 모두. Codex 로컬 SQLite의 cwd·갱신 시각, Claude Code JSONL의 cwd, Cursor workspace 메타데이터를 읽습니다. 모든 도구는 직접 폴더 연결도 제공합니다. 이력에서 발견한 프로젝트는 사용자가 체크하기 전까지 자동 정리 대상이 아닙니다. 도구 버전별 이력 형식이 달라 읽지 못할 수 있습니다.
- 메모리 압박 연동(2.2.1): 주의/부족 상태가 30초 이상 이어지면 작업 확인 안내만 표시합니다. 프로젝트 파일 정리를 자동으로 실행하지 않으며 기존 자동화 설정은 업그레이드 시 꺼집니다.
- 실행 직전에 프로세스·작업 경로·작업 이력·파일 상태를 다시 확인합니다. 같은 프로젝트의 여러 생성물을 이동할 때 정리 자체가 바꾼 부모 폴더 시각은 구분하면서 소스 변경·삭제는 거부합니다. 결과와 실패 이유는 기존 정리 기록에 남깁니다.

프로젝트 정리는 디스크 관리 기능입니다. 실행 중인 AI 프로세스의 RAM을 직접 회수하지 않습니다. 메모리를 줄이려면 AI 관리에서 앱을 검토해 종료하세요. 디스크 공간은 휴지통을 비운 뒤 확보되며, 이 기능은 휴지통을 자동으로 비우지 않습니다.

이력 형식 확인 자료: [Claude Code 세션 경로 관련 공식 저장소 이슈](https://github.com/anthropics/claude-code/issues/31950), [Cursor workspace 메타데이터 관련 공식 포럼](https://forum.cursor.com/t/file-read-backend-unavailable/162116). Codex 형식은 현재 Mac의 로컬 데이터베이스에서 확인했습니다. [Hermes 세션 문서](https://hermes-agent.nousresearch.com/docs/user-guide/sessions/)는 세션 저장을 설명하지만 프로젝트 경로 자동 연동은 이 버전에 포함하지 않습니다.

- 한눈에 보기: 실제 CPU·메모리·압박·스왑·디스크 상태. 전체 검사 한 번으로 캐시·로그·개발 캐시, 큰 파일·중복·오래된 파일·설치 파일·유사 사진·폴더 용량, 설치 앱·잔여물을 모아서 확인합니다.
- 권한 설정: 검사 전에 파일 접근과 선택 기능의 권한을 한 화면에서 확인합니다. 권한 변경 후 한 번 재실행하면 요청한 전체 검사를 자동으로 이어갑니다.
- 검사 결과: 오래된 캐시·로그와 동일한 파일 사본을 자동으로 추리고, 선택 항목 정리로 일괄 휴지통 이동. 추천 종류 제외·상세 검토, 실행 직전 재검증, 원본 보관, 항목별 실패 기록을 제공합니다. 자세한 범위와 미지원 기능은 [CleanMyMac 비교 리뷰](docs/cleanmymac-review.md)를 참고하세요.
- 저장 공간 정리: `~/Library/Caches`, `~/Library/Logs`의 개별 항목 확인과 선택한 항목의 휴지통 이동. 실행 앱 ID와 정확히 일치하는 폴더는 건너뜁니다.
- 개발 캐시: Xcode Build/Index/noindex 생성물, npm/pip/Homebrew/Yarn/pnpm 캐시. 실행 도구와 최근 변경을 확인하고 설정한 보관 기간이 지난 개별 파일을 추천. Archives와 패키지 저장소는 유지합니다.
- 폴더 용량: 크기순 폴더 지도·하위 탐색·직접 선택 정리. 논리 크기 기준이며 링크·하드 링크·미다운로드 iCloud 파일을 구분합니다.
- 유사 사진: macOS Vision의 로컬 CPU 비교, 미리보기, 보관 사진 교체와 수동 정리. 최대 200장, 거리 기준 0.35. 보관 사진은 자동 추천에서도 보호합니다.
- 오래된 파일·설치 파일: 180일 이상 미변경 파일, dmg/pkg/iso를 분류해서 직접 검토.
- 큰 파일: 선택한 폴더의 100 MB 이상 파일. 중복 파일: 크기 → 스트리밍 SHA-256 → 실제 바이트 비교. 그룹마다 원본 한 개를 보관합니다.
- CPU·메모리: 프로세스별 실시간 CPU 변화량, 앱과 도우미 프로세스 합산 사용량. CPU 50% 이상 또는 앱 합산 메모리 1 GB 이상인 앱을 추려 선택할 수 있습니다. 선택한 GUI 앱에 일반 종료를 일괄 요청하고 필요할 때 별도로 강제 종료합니다. 종료 요청 전후 시스템 수치를 관측합니다.
- 앱 관리: `/Applications`, `~/Applications`의 사용자 설치 앱. 앱 ID가 정확히 일치하는 캐시·로그·환경 설정·Application Support·컨테이너를 확인합니다. 앱 이름을 쓰거나 여러 앱이 공유하는 지원 폴더는 자동 추정하지 않습니다.
- 앱 잔여물 후보: 설치/등록/실행 앱 ID 확인 후 Preferences·지원 파일·Containers·캐시 등의 미등록 후보를 표시. 실제 제거 여부는 직접 판단하며 이동 직전 상태를 다시 확인합니다.
- 휴지통 비우기: 현재 사용자 휴지통을 검사하고 확인한 목록만 영구 삭제. 검사 후 변경·추가 항목은 유지하고 실패는 기록합니다. 개발 검증은 임시 폴더만 사용했습니다.
- 유지보수: DNS 초기화·Spotlight 재색인 요청·Time Machine 로컬 스냅샷 목록 및 선택 제거. 확인 후 OS 관리자 인증으로 고정 명령을 실행합니다. 스냅샷 제거는 영구 삭제이며 실제 개인 백업을 테스트로 제거하지 않았습니다.
- 메뉴 막대: 실시간 CPU·메모리·저장 공간·배터리·네트워크 송수신률. 설정에서 지속적인 과부하 알림과 로그인 실행을 켤 수 있습니다.
- 정리 기록: 최근 500건의 실제 결과와 실패 이유를 `~/Library/Application Support/DonyClean/history.json`에 저장합니다.

## 파일과 앱 보호

직접 선택한 항목 또는 검토한 추천 목록을 native 확인 창에 전체 경로를 표시하고 이동합니다. 검사 후 파일·디렉터리 내용·부모 경로가 변경되면 작업을 거부합니다. 중복 사본은 원본이 그대로 남아 있을 때만 이동합니다. 휴지통 이동은 즉시 디스크 공간 확보로 계산하지 않습니다. 유지보수에서 현재 사용자 휴지통의 검사한 항목을 영구 삭제할 수 있습니다. 전체 경로 확인과 기본 취소를 거치며 새로 들어온 항목은 제외합니다. 영구 삭제 후에는 복원할 수 없습니다. 휴지통 이동 상태의 복원은 Finder에서 합니다. 접근이 거부되면 시스템 설정에서 필요한 파일 접근 권한을 직접 관리하세요.

앱 종료는 현재 사용자 소유의 일반 GUI 앱만 가능합니다. PID, 시작 시각, UID를 다시 확인하고 시스템 프로세스와 도니홈 자체를 보호합니다. CPU·메모리 정리는 선택한 앱 종료를 통해 자원을 회수합니다. `purge`, 스왑 파일 삭제, 메모리 강제 할당 같은 동작을 수행하지 않습니다.

검사 중단·읽기 권한 부족·변경된 파일은 결과에 표시됩니다. macOS가 접근을 제한하는 폴더는 앱에서 권한을 우회하지 않습니다. 원하면 시스템 설정에서 접근 권한을 직접 관리할 수 있습니다.

악성코드 검사와 타사 앱 자동 업데이트는 이번 버전에 포함하지 않습니다. 앱별 합산 메모리에는 공유 메모리가 중복될 수 있고, CPU는 코어당 100%라 앱 수치가 100%를 넘을 수 있습니다. 클라우드 검사는 iCloud의 다운로드 상태를 확인하며 모든 타사 클라우드 공급자를 보장하지 않습니다.

`--diagnostics`, `--smart-plan`, `--snapshots`, `--scan`은 읽기 전용입니다. `--smart-plan --folder /경로`로 파일 범위를 지정할 수 있습니다. 파일 작업 테스트는 매 실행마다 만든 임시 파일만 사용하고, 테스트 파일의 휴지통 이동 후 복원·정리합니다.

이 Mac의 Command Line Tools에는 XCTest가 없어 Swift Testing을 사용합니다. 테스트 스크립트는 해당 프레임워크와 매크로 플러그인을 명시적으로 연결합니다. 설치된 macOS 27 SDK의 SwiftUI 플러그인 누락을 피하기 위해 macOS 26.5 SDK가 있으면 이를 사용합니다. `DONY_SDK_PATH`로 빌드 SDK를 지정할 수 있습니다.
